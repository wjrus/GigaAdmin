# Application audit — September 29, 2026

This pass covered controllers, models, services, jobs, helpers, views, JavaScript,
initializers, runtime configuration, command-line tasks, deployment scripts,
tests, and public documentation. Changes were verified locally without accessing
the production application or either Plex host.

## Correctness and security

- Pending invitations must belong to the configured Plex server. An email match
  alone cannot cache or cancel an invitation for another server or a friendship.
- Cover responses accept a specific raster-image MIME allowlist; SVG and malformed
  responses fail safely. Cover links strip embedded Plex tokens.
- `ADMIN_USERS` is the single administrative allowlist. The undocumented singular
  `ADMIN_USER` fallback was removed; older installations using it must rename it.
- Invalid form structures return controlled errors, and missing user pages return
  404. CSV values escape additional spreadsheet formula prefixes.
- Malformed Plex responses cannot silently replace cached data with an empty
  result. Transport failures use safe messages rather than raw response fragments.
- Completed refresh jobs skip duplicate deliveries. Maintenance polling replaces
  its panel rather than nesting another poller and stops when the refresh finishes.
- Error messages persist until dismissed. Native user links preserve table and
  keyboard semantics; confirmation dialogs support Escape; blocked browser storage
  does not break theme selection.

## Performance

- Bulk sharing changes write one snapshot, retaining successful changes if a later
  Plex request fails. External Plex changes are still not transactional.
- Overlapping history imports skip PostgreSQL updates when the stored payload has
  not changed. A regression test checks that the physical row is not rewritten.
- Latest-per-account queries use indexed lookups instead of scanning each user's
  history. With 200,000 synthetic events and 100 accounts locally, the query changed
  from 68.568 ms / 202,505 shared-buffer hits to 0.602 ms / 900 hits. These are local
  query measurements, not a claim about production latency.
- User-history CSV export streams in 1,000-row batches without first computing the
  dashboard. Known shared-user pages avoid scanning every local playback account.
- Reports are reused within requests; grouped maximums and top-ten rankings are
  reduced in SQL. Cached Now Playing results retain their observation timestamp
  and are isolated by server configuration.

## Activity and rankings

The old per-session sampler loop is replaced by a recurring Rails job. It records
one aggregate row per minute, including idle observations, for concurrency,
delivery-method, transcoding, and estimated-bandwidth graphs. No new usernames,
device details, or IP addresses are stored by this collector. Old detailed rows
remain readable and are not deleted by the migration or new retention task.

Activity retention defaults to 90 days, with strict configuration validation and
batched daily pruning. Failed observations leave gaps, and queued observations
that are too old are skipped rather than replayed. Charts query bounded time
buckets and show coverage; Plex bandwidth is an estimate, not interface throughput.

Top-ten movies, shows, and users use imported playback history with rolling day,
week, month, three-month, six-month, year, and all-time windows. Show rankings sum
episode plays by series. Existing completion and daily deduplication rules remain
in place and are explained on the page and in the [feature guide](features.md).

The deployment script retires a legacy sampler container only after the new web
service passes its health checks. The migration is additive. See the
[upgrade instructions](deploy.md#automatic-activity-collection).

## Verification and limits

- Full Rails suite: 290 tests, 2,164 assertions, no failures or errors.
- JavaScript: 18 tests passed; RuboCop, Brakeman, gem and importmap audits passed.
- Production eager loading and asset compilation passed without a database.
- A real production-mode Solid Queue scheduler and worker, connected only to
  disposable local databases and a synthetic HTTP server, recorded active and idle
  polls. A subsequent HTTP 503 recorded no row. All smoke-test processes stopped.
- Browser checks covered graphs, period filters, light/dark styling, a phone-sized
  viewport, maintenance polling completion, and persistent error alerts.

Docker is unavailable on the development machine, so the container build and
fresh-install check run in GitHub CI. No production deployment occurred during
this audit. Actual Plex API compatibility and operating load still need observation
after deployment; aggregate graphs cannot reconstruct activity from before it.
